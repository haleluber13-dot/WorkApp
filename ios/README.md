# יומן הפקה — אפליקציית iOS נייטיב

פרויקט SwiftUI מלא, מקביל ל־PWA שבתיקיית `web/`. שתי האפליקציות משתמשות
באותו מבנה נתונים ובאותו פרויקט Supabase.

---

## ⚠️ לפני שמתחילים

**הקוד הזה לא עבר קומפילציה.** הוא נכתב בסביבת לינוקס שאין בה Xcode או
קומפיילר Swift, ולכן אי אפשר היה לבנות או להריץ אותו. המבנה נבדק אוטומטית
(איזון סוגריים, פתרון סמלים בין קבצים, ייבואים חסרים), אבל בבנייה הראשונה
סביר שיהיו שגיאות קומפילציה קטנות שצריך לתקן ב־Xcode.

ה־PWA שבתיקיית `web/`, לעומת זאת, **כן נבדקה והורצה** — בדפדפן במצב אייפון,
כולל בדיקות אוטומטיות מקצה לקצה.

---

## מה צריך

* מק עם **Xcode 15 או חדש יותר**
* iOS 17 ומעלה במכשיר היעד
* חשבון Apple — חינמי מספיק כדי להריץ, אבל האפליקציה תפוג אחרי 7 ימים.
  חשבון Apple Developer (99$ לשנה) משאיר אותה מותקנת לצמיתות.

## בנייה — עם XcodeGen (מומלץ)

```bash
brew install xcodegen
cd ios
xcodegen generate
open WorkApp.xcodeproj
```

ב־Xcode: בוחרים את הטארגט `WorkApp`, לשונית **Signing & Capabilities**,
ומסמנים את ה־Team שלכם. אז ⌘R.

## בנייה — בלי XcodeGen

1. ב־Xcode: **File → New → Project → iOS → App**.
2. שם: `WorkApp`. Interface: **SwiftUI**. Language: **Swift**.
3. מוחקים מהפרויקט את `ContentView.swift` ואת קובץ ה־`App` שנוצרו אוטומטית.
4. גוררים לפרויקט את התיקייה `ios/WorkApp` — מסמנים **Copy items if needed**
   ו־**Create groups**.
5. ב־**Build Settings** מפנים את `INFOPLIST_FILE` אל
   `WorkApp/Resources/Info.plist`, או מעתיקים ממנו את המפתחות ל־Info.plist
   שנוצר אוטומטית. חשוב במיוחד:
   * `NSLocationWhenInUseUsageDescription` — בלעדיו האפליקציה **קורסת**
     ברגע שלוחצים על "השתמש במיקום הנוכחי שלי".
   * `CFBundleDisplayName` = `יומן הפקה`
6. **Deployment Target**: iOS 17.0.

## מבנה הקוד

```
WorkApp/
  WorkAppApp.swift          נקודת הכניסה, שמירה ברקע, סנכרון בכניסה
  Models/
    Model.swift             כל הגיליונות, העמודות והרשומות
  Services/
    Store.swift             מצב מקומי + שמירה לדיסק (מקור האמת של הממשק)
    Sync.swift              סנכרון אופציונלי מול Supabase
    Actions.swift           חיוג, וואטסאפ, ניווט, שיתוף, צבעים
    OneShotLocator.swift    קריאת מיקום חד־פעמית
  Views/
    RootView.swift          חמש הלשוניות
    TodayView.swift         מסך היום + סרגל אנשי הקשר
    CrewView.swift          ספר אנשי הקשר
    DaysView.swift          לוח הצילומים
    SheetsView.swift        חמשת הגיליונות (תצוגת יום + טבלה)
    SettingsView.swift      מיקומים, ניווט, מראה, סנכרון
    Editors.swift           כל חלונות העריכה
    Components.swift        רכיבים משותפים
```

## החלטות תכנון

**מקומי קודם.** `Store` הוא מקור האמת של הממשק, תמיד. הוא נשמר לקובץ JSON
ב־Application Support ונטען מיידית בהפעלה. סנכרון הוא תיאום ברקע — לעולם
לא חוסם. בסט אין קליטה, וזה המצב הרגיל ולא החריג.

**עברית ננעצת.** `RootView` קובע `layoutDirection` ל־RTL ולא נשען על שפת
המכשיר — איש צוות עם טלפון באנגלית עדיין צריך לראות את הגיליון בכיוון שבו
הוא נבנה.

**ניגודיות מחושבת.** צבעי המחלקות נעים מכהה מאוד לבהיר מאוד. `Color.ink(on:)`
בוחר טקסט לבן או כמעט־שחור לפי בהירות ה־WCAG, כי לבן קבוע לא נקרא על הצהוב
של מחלקת התאורה.

**רשומות עם חותמת זמן.** לכל רשומה יש `updatedAt` שנקבע בלקוח, וזה מה שמאפשר
סנכרון "אחרון מנצח" בלי סבב לשרת.

## אם משנים את מבנה הגיליון

כל העמודות מוגדרות במקום אחד — `Sheets` ב־`Models/Model.swift`. הוספת
עמודה היא שורה אחת שם, והיא מופיעה גם בתצוגת היום וגם בטבלה המלאה.

**חשוב:** אותו שינוי צריך להיעשות גם ב־`web/js/model.js`, אחרת שתי
האפליקציות לא יסכימו על מה שמסונכרן ביניהן. מפתחות ה־`slot` חייבים להיות
זהים בדיוק.
